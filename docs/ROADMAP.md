# Roadmap: launch-ready multi-tenant Saarthi

Status: **approved (D1-D10 resolved below).** Each step is one small commit (reviewable in under 30 minutes) pushed straight to `main` after its focused tests pass; the full `make test` runs at the end of each step.

## 1. What the repo looks like today (shapes the plan)

- **Background work** is `BackgroundTasks` (`launch_flow.py:153`) plus APScheduler in-process (`scheduler.py`, advisory lock, one uvicorn worker).
- **Limits and budget:** `ratelimit.py` is an in-memory per-IP deque. The token budget is a constant `TOKEN_BUDGET = 50000` with usage in `.ai_token_usage.json`, and the LLM cache is `.ai_cache/` on local disk (`agents/launch.py`). Neither survives a second API process.
- **Not tenant-keyed.** Only `practice_invites`, `therapist_profiles`, `pending_actions` and `agent_runs` carry `practice_id`. Clinical tables (`sessions`, `case_plans`, `assessments`, `alerts`, `case_memory_chunks`, `journal_entries`, and others) key on `client_id` and `therapist_user_id`. Clients are global users and may book with several practices. RLS therefore needs a schema step first (M1-09).
- **DB role:** compose connects as the `postgres` superuser, which bypasses RLS. A non-owner, `NOBYPASSRLS` application role is required for any RLS test to mean anything.
- **RAG:** 12 KB entries, one chunk per entry, `to_tsvector('english', ...)`, no vector index, 20-candidate RRF, one global `KB_MIN_SIMILARITY`. `main.py` is 1,460 lines, so new routers go in new modules rather than growing it.
- **Edge:** Caddy serves a single `{$DOMAIN}` with `/api/*` proxied. No CSP, no on-demand TLS, no wildcard.
- **No CI** (`.github/` absent), no LICENSE, no lint or type-check config.

## 3. Invariants and how every PR proves them

Introduced as M1-02 and run in CI on every PR (`tests/invariants/`):

| Invariant | Executable check |
|---|---|
| AI only proposes | Every agent entrypoint, run with a stubbed LLM, leaves target tables unchanged and creates a `pending_action`; applying requires an authenticated human call with `Idempotency-Key`; replaying the key is a no-op. |
| Crisis path has no LLM | The Anthropic client and embeddings-over-network are patched to raise; every client free-text endpoint and PHQ-9 item 9 > 0 still returns the fixed Tele-MANAS 14416 message and creates a high-priority alert. |
| Server-side access | A registry test enumerates all routes from the OpenAPI schema and fails if a route lacks an entry in the access-control test matrix (cross-client, cross-therapist, owner-to-clinical, cross-tenant). New endpoints cannot ship untested. |
| Post-check on all AI output | A registry test fails if an agent output type is not routed through `post_check` (diagnoses, medication or supplement advice, unsupported claims). |
| Manual workflows when AI is down | The suite runs with no key and with the budget exhausted; booking, notes, approvals and the safety path pass. |
| Synthetic data only | A seed and eval lint rejects real-looking emails and phone numbers outside `example.*` and reserved ranges. |

Every PR description carries: what changed, how to verify, tests and before/after numbers, invariants touched, open risks, next step.

## 4. Conventions

- Test commands: `make test` (backend), `npm run build` and `npm run check` (frontend), `make e2e`, plus `make eval-safety` and `make eval-rag` once they exist. Focused tests first, full suite at the end of each PR.
- Every table has an Alembic migration; tests run `alembic upgrade head` on real Postgres (pgvector image).
- ADR per decision in `docs/adr/NNNN-title.md` (context, options considered, decision, consequences). ADRs are listed against the steps below.
- Docs updated in the same PR; README numbers only come from committed scripts.
